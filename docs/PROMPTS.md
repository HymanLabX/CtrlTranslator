# 给 Codex 的 Prompt（按顺序，一次一段）

> **使用方法**：在项目目录下打开 PowerShell，把下面对应里程碑的整段文字
> 复制粘贴给 Codex（`codex` 进入交互模式后粘贴，或 `codex "……"` 直接传入）。
>
> **纪律**：
> 1. **一次只给一段**，前一个里程碑验收全过之前，绝不粘下一段。
> 2. Codex 说做完之后，打开 `docs/MILESTONES.md` 照着验收清单**逐条点**。
> 3. 有不过的项，用文末的「返工模板」描述现象，让它修。
> 4. 全过了再 `git commit`，然后进入下一段。

## M2.1 · 补丁：关闭模型思考模式

> 实测发现的问题。M2 其余部分已验收通过，这是一个**小范围补丁**，不是重做。

```
SPEC 已更新，请先重新阅读 docs/SPEC.md 的这三处，然后按新 SPEC 给 M2 打补丁：
- §5.1 末尾新增的「额外请求参数（ExtraRequestBody）」小节
- §5.6 黄色警告条的三个按钮行为（新增了「关闭思考模式」）
- §7.1 设置表中新增的「额外请求参数」一行

背景：实测 deepseek-v4-flash 翻一句话要 4 秒，因为 DeepSeek V4 的 thinking 参数
默认是 enabled。各厂商写法不同，所以要做成通用的 JSON 合并机制，不要写死某一家。

本次改动范围严格限定为以下四点，不要动任何其他已通过验收的功能：

1. AppSettings 增加 ExtraRequestBody 字段，默认值 {"thinking": {"type": "disabled"}}。
   注意：老的 settings.json 里没有这个字段，反序列化后要能自动补上默认值，
   不能因为字段缺失就让配置读取失败。
2. OpenAiCompatibleClient 构造请求体时，把 ExtraRequestBody 浅合并进顶层，
   同名键以 ExtraRequestBody 为准。为空或 JSON 非法时跳过合并并写日志，
   绝对不能因此让翻译失败。
3. 浮窗的黄色警告条增加「关闭思考模式」按钮，行为见 §5.6 的表格：
   写入设置 → 保存 → 立刻用新参数重译当前这段文字 → 成功则提示条消失。
4. 临时的「填写 API Key…」窗口增加这个字段（多行文本框即可）。
   §7.1 说的那一排预设按钮属于 M3 的正式设置页，本次不做。

完成后必须自己执行 dotnet build -c Release 确认 0 警告 0 错误。

做完后请说明：改了哪几个文件、老配置文件的兼容性怎么保证的、
以及 JSON 非法时的具体行为。
```

**补丁验收（4 条，你自己点）**

| # | 怎么验 | 通过标准 |
|---|---|---|
| 1 | 划一句英文翻译 | **明显比之前快**（之前 4 秒，现在应在 1–2 秒），且**不再出现黄色警告条** |
| 2 | 打开 `%APPDATA%\CtrlTranslator\settings.json` | 有 `ExtraRequestBody` 字段，值是 `{"thinking":{"type":"disabled"}}` |
| 3 | 把该字段手工改成一段乱码（如 `{{{`），重启，再划词 | 翻译**仍然正常**（只是变慢，因为参数被忽略），不报错不崩溃 |

## 卡住了怎么办

**同一个问题让 Codex 修了两轮还不好**，就停下来，把下面这些东西发给 Claude：

1. 卡在哪个里程碑的第几条验收
2. `%APPDATA%\CtrlTranslator\logs\` 里最新的那个日志文件
3. Codex 最后一轮的回复
4. `dotnet build -c Release` 的完整输出

别在同一个坑里反复让 Codex 试 —— 它会越改越乱，而你看不出来。
