## M0 · 骨架与托盘

**目标**：有一个能编译、能运行、能干净退出的空壳程序。
这个里程碑不做任何划词和翻译功能，专门解决"地基"。

### 交付范围

- `CtrlTranslator.sln` + `src/CtrlTranslator/CtrlTranslator.csproj`
  （`net10.0-windows`、`UseWPF`、`UseWindowsForms`、`nullable enable`、
  `ApplicationIcon`、版本信息）
- `app.manifest`，声明 **Per-Monitor DPI Awareness V2**
- `App.xaml.cs`：
  - **单实例**（用命名 `Mutex`；第二个实例启动时激活已有实例的主窗口后自行退出）
  - **无启动窗口**（`ShutdownMode = OnExplicitShutdown`，启动时不显示任何窗口）
  - 全局异常兜底三件套（见 SPEC §9.3）
- `Diagnostics/Logger.cs`：按天分文件、14 天自动清理、Key 脱敏
- `Settings/AppSettings.cs` + `SettingsStore.cs`：
  JSON 读写、DPAPI 加解密、原子写入、损坏时备份重建
- `Settings/BuiltInModes.cs`：把 SPEC §5.5 的四个内置模式写死为默认值
- `UI/TrayIconController.cs`：托盘图标 + 完整右键菜单（菜单项可点击，
  但"设置""主窗口""诊断"暂时弹一个"该功能将在后续里程碑实现"的提示框即可）
- `Assets/` 下放一个正常图标和一个灰色图标（可以用简单的几何图形自行生成 `.ico`）
- 数据目录自动创建：`%APPDATA%\CtrlTranslator\` 与其下的 `logs\`

| 1 | 终端里跑 `dotnet build -c Release` | 输出 `0 个警告，0 个错误` |

## M1 · 划词取词（最难的先攻）

**目标**：双击 Ctrl 能可靠地拿到你选中的文字，并且**不破坏你的剪贴板**。
这个里程碑**不做翻译、不做浮窗**——取到的文字用托盘气泡显示出来即可。

先攻这里是因为：这是整个项目技术风险最高的一环，
如果这里搞不定，后面做再多界面也没意义。

### 交付范围

- `Interop/NativeMethods.cs`：本里程碑需要的所有 Win32 声明
- `Interop/LowLevelKeyboardHook.cs`：`WH_KEYBOARD_LL` 的安装/卸载/回调封装
  （回调必须遵守 AGENTS.md §5.2 的禁区规则）
- `Core/DoubleTapDetector.cs`：SPEC §2.1 的状态机
- `Core/ForegroundApp.cs`：取前台窗口进程名
- `Core/TextCapture.cs`：SPEC §3.1 的完整取词与剪贴板还原流程（含重试）
- `Core/AppState.cs`：全局暂停开关、防抖（~~黑名单检查~~ · **应用黑名单功能已删除**）
- 取词成功后：托盘气泡显示 `取到 {n} 字：{前50字}`，并写日志
- 设置里的黑名单暂时可以直接改 `settings.json` 手工测试（M3 才做设置界面），
  但**黑名单的读取与判断逻辑必须在本里程碑实现**

### ✅ 验收清单（M1）

| # | 怎么验 | 通过标准 |
|---|---|---|
| 1 | `dotnet build -c Release` | 0 警告 0 错误 |
| 2 | 记事本里打一句话，选中它，快速双击 Ctrl | 右下角气泡显示出你选中的那句话 |
| 3 | 在**浏览器**里选一段网页文字，双击 Ctrl | 能取到 |
| 4 | 在 **Word**（或 WPS）里选一段，双击 Ctrl | 能取到 |
| 5 | 在 **PDF 阅读器**里选一段，双击 Ctrl | 能取到 |
| 6 | 在**微信/QQ**聊天记录里选一段，双击 Ctrl | 能取到 |
| 7 | 🔴 **剪贴板还原测试**：记事本里复制文字 A（Ctrl+C），然后选中另一段文字 B，双击 Ctrl，最后在别处 Ctrl+V | **粘出来必须是 A，不是 B** |
| 8 | 选中文字，按住 Ctrl 不放然后按 C（正常复制） | **不触发**任何气泡 |
| 9 | 选中文字，按住 Ctrl 不放然后按 A、V、S 等 | **不触发** |

> 这个软件会污染用户的剪贴板，属于**严重缺陷**，必须修好才能继续。

## M2 · 翻译闭环

**目标**：划词 → 翻译 → 浮窗显示。核心价值在这个里程碑跑通。

### 交付范围

- `Translation/OpenAiCompatibleClient.cs`：流式 SSE 解析、单例 HttpClient、
  连接预热与保活、超时与取消（SPEC §5.1 §5.2）
- `Translation/PromptBuilder.cs`：模式模板 + 占位符替换 + 词/句判定 + 语言方向（§3.4 §5.3 §5.4）
- `Translation/ModelHeuristics.cs`：推理模型三重检测（§5.6）
- `Translation/TranslationService.cs`：编排（查缓存 → 请求 → 写库），
  新请求取消旧请求
- `Data/Database.cs` + `HistoryRepository.cs`：建表、缓存查询、写入（§6.2 §6.3）
- `Diagnostics/ErrorMessages.cs`：SPEC §9.1 的**完整**错误映射表
- `Interop/LowLevelMouseHook.cs` + `Interop/DpiHelper.cs`
- `UI/PopupWindow.xaml(.cs)`：SPEC §4 全部内容
  （定位算法、关闭行为、工具条、加载态与计时、流式回退、词典渲染、主题）
- 长文本二次确认对话框（§3.3）
- 浮窗上的 ☆ 收藏按钮本里程碑要能用（写数据库 `starred` 字段），
  但查看收藏的主窗口留到 M3

### 前置条件

验收前需要先手工在 `settings.json` 里填好 Base URL / Key / Model
（Key 要用程序写入，所以本里程碑需要提供一个临时手段：
接受在托盘菜单里加一个临时的「填写 API Key…」输入框，M3 会被正式设置页取代）。

## M3 · 设置 / 向导 / 诊断 / 生词本

**目标**：让这个软件从"能跑"变成"能配、能自查、能回看"。
本里程碑之后，你应该完全不需要再手工编辑任何文件。

### 交付范围

- `UI/SettingsWindow.xaml(.cs)`：SPEC §7 的五个页签**全部**内容，
  包括「触发方式」页签里的**实时双击测试区**（§7.3）
- 模式管理：新建 / 编辑 / 删除 / 恢复默认（§7.2）
- 「拉取可用模型」功能（§7.1）
- `Diagnostics/DiagnosticRunner.cs` + 诊断窗口：SPEC §10 的 12 项检查，
  逐项实时显示 ✓/✗/⚠ + 耗时，底部「复制诊断报告」（Key 必须脱敏）
- `UI/OnboardingWindow.xaml(.cs)`：SPEC §11 的四步向导，内置 §5.7 的服务商预设
- `UI/MainWindow.xaml(.cs)`：两页签（全部历史 / 我的收藏）、搜索、
  详情区、右键菜单、CSV 导出（§6.4）
- 托盘菜单里的所有项**全部接通**（不再有"后续实现"的占位提示）
- 移除 M2 里那个临时的「填写 API Key…」入口

## M5 · 多服务商档案与自动降级

**目标**：从"一个 Key 写死"变成"几个服务商排队顶上"。
主服务商秒级失败时自动改用备用，你基本察觉不到；真正需要动手的故障（Key 废了、
余额空了）会主动告诉你，而不是让你对着一句"翻译失败"发懵。

### 交付范围

- `Settings/ApiProfile.cs`：一个档案 = 名称 + BaseUrl + Key + Model + **ExtraRequestBody**
  + Temperature/MaxTokens/超时 + 失效标记。关闭思考的写法各家不同，
  必须跟着档案走，否则切到别家会带着上一家的参数发过去
- `Settings/ProviderPresets.cs`：服务商预设合并为一份（原先设置窗和向导各有一份，会走样）
- `AppSettings.Profiles` / `CurrentProfileId` / `BuildFailoverChain()`；
  **列表顺序即降级顺序**，一次最多试 `MaxFailoverAttempts` = 3 个（1 主 + 2 备）
- `SettingsStore`：多档案 DPAPI 加解密；**旧版单服务商配置首次启动自动迁移成「档案 1」**
- `Translation/FailoverPolicy.cs`：秒级失败才降级
  - 持久故障（401 / 余额不足 / 模型不存在 / 配置不全）→ 切备用**并标记失效**
  - 瞬时故障（429 / 5xx / 连不上）→ 切备用但**不**标记，下次照常先试它
  - 超时 / 返回非 OpenAI 兼容格式 → **不降级**，直接报错
- `TranslationService`：降级编排；缓存 key 用本次实际使用的模型名，绝不串台
- `usage` 字段尽力而为地存进数据库（`prompt_tokens` / `completion_tokens` / `profile_name`），
  **不做统计界面**
- 设置窗口重做：横向页签 → 左侧导航 + 右侧卡片；「翻译服务」拆成「服务商档案」+「模型参数」
- **删除独立诊断窗口**，365 行检查逻辑保留，下放为每个档案旁的「测试」按钮，结果就地展开
- 托盘：新增「翻译服务」子菜单（失效档案带 ⚠）；有档案失效时图标带红色角标
- 浮窗：多一行「XX 暂时不可用，已自动改用 YY 翻译」，**布局其余部分一个像素不动**
- 引导向导：改成建第一个档案；原「一键诊断…」改为就地跑 12 项检查并列出结果

## M6 · 自动更新与发布收敛

**目标**：你和朋友装上之后，以后不用再跑一趟 GitHub。
程序自己发现新版本、下载、**校验**、装上、重启。

### 交付范围

- **发布产物收敛为一个**：Release 只上传 `CtrlTranslator-Setup-*.exe`，别的什么都不发。
  免安装裸 exe 不再发布（它没法安全地自我更新），但**仍然会构建** —— 它是安装包的输入，
  也是你本机验证打包产物的东西
- `Update/UpdateChecker.cs`：查 `/releases/latest`（天然跳过预发布），比对版本
- `Update/UpdateDownloader.cs`：下载 → **强制校验 SHA256** → 启动静默安装。
  哈希对不上就删文件、报错，**没有开关也没有例外**
- `Update/InstallationInfo.cs`：从 Inno 的 `AppId_is1` 注册表项判断是安装版还是裸 exe、
  是否全机器安装（决定要不要提权）。还会核对当前 exe 是否真在安装目录里 ——
  装过一次又拷了个裸 exe 出来的情况必须按裸 exe 处理
- `Update/UpdateService.cs`：启动后 15 秒查一次 + 之后每 24 小时；
  点过「稍后」的版本不再自动弹窗
- `UI/UpdateWindow.xaml(.cs)`：更新说明 + 下载进度 + 立即更新 / 稍后 / 打开发布页
- 安装脚本：`InitializeSetup` 里等旧进程的互斥体消失（最多 10 秒）再继续；
  静默安装完成后用 `runasoriginaluser` 把程序拉回来
- 设置 → 关于：「自动检查新版本」开关 + 「检查更新」按钮

### 前置条件

**发版前必须把 `src/CtrlTranslator/CtrlTranslator.csproj` 里的 `Version` /
`AssemblyVersion` / `FileVersion` 三处改成新版本号**，否则装上新版后程序仍然自认为是旧版本，
会永远提示"有更新"。

  「打开发布页面」的出口，**不做任何第三方镜像回退** —— 镜像给回来的文件不可信，
