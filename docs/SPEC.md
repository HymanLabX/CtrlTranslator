# CtrlTranslator v1.0 需求规格书

> 唯一事实来源。实现时如与本文档冲突，以本文档为准。
> 本文档只描述 v1.0 范围内的需求；§13 列出的功能**明确不做**。

---

## 1. 产品定义

Windows 桌面常驻小工具。用户在**任意程序**中选中文字后**快速双击 Ctrl 键**，
鼠标附近弹出浮窗显示译文。翻译由用户自备的 OpenAI 兼容大模型接口完成。

- 无主界面常驻，只有系统托盘图标
- 典型使用场景：读英文学术论文、看外文网页新闻、写商务邮件
- 目标延迟：短句从双击到出结果 **1 秒内**（缓存命中时 0ms）

## 2. 触发机制

### 2.1 双击检测算法

使用低级键盘钩子 `SetWindowsHookEx(WH_KEYBOARD_LL, ...)`，安装在 WPF 主线程
（主线程有消息循环，钩子才能收到回调）。

**术语定义：一次「有效敲击」** = 触发键（默认 Ctrl，含左右 Ctrl）
按下 → 抬起的一个完整周期，且满足：

1. 按下到抬起的时长 `< MaxKeyHoldMs`（默认 400ms）—— 排除长按
2. 从按下到抬起期间，**没有任何其他按键的 KEYDOWN 事件**
   —— 这是排除 `Ctrl+C`、`Ctrl+V`、`Ctrl+A` 等组合键的关键
3. 期间没有鼠标点击

**触发条件**：连续两次有效敲击，且第二次的抬起时刻与第一次的抬起时刻之差
`< DoubleTapIntervalMs`（默认 350ms）。

**触发后立即重置状态机**，使得连按三下只触发一次，不会触发两次。

**状态机字段**（全部为简单值类型，无锁访问）：

```
long  _lastTapReleaseTicks   // 上一次有效敲击的抬起时间戳
long  _currentPressTicks     // 本次按下的时间戳，0 表示当前未按下
bool  _pollutedByOtherKey    // 本次按下期间是否出现了其他键
```

**处理逻辑**：

| 事件 | 动作 |
|---|---|
| 触发键 KEYDOWN（且 `_currentPressTicks == 0`）| 记录 `_currentPressTicks = now`，`_pollutedByOtherKey = false` |
| 触发键 KEYDOWN（重复，来自键盘自动重复）| 忽略 |
| 其他键 KEYDOWN | `_pollutedByOtherKey = true` |
| 触发键 KEYUP | 计算是否为有效敲击 → 判定是否触发 → 重置 `_currentPressTicks = 0` |

> **实现要点**：Windows 的按住不放会产生连续 KEYDOWN，必须靠 `_currentPressTicks != 0`
> 去重，否则长按会被误判成连续敲击。

### 2.2 触发后的前置检查（按顺序，任一不通过则静默返回）

1. 全局暂停开关是否打开（`AppState.Enabled == false` → 返回）
2. 取当前前台窗口所属进程名（`GetForegroundWindow` → `GetWindowThreadProcessId`
   → `Process.GetProcessById().ProcessName`），若在黑名单中 → 返回
3. 上一次触发距今 `< 500ms` → 返回（防抖）
4. 前台窗口是 CtrlTranslator 自己的窗口 → 返回

### 2.3 已知限制（必须在 README 和"关于"页面里向用户说明）

- **UIPI 限制**：以普通权限运行时，钩子收不到以管理员权限运行的程序
  （任务管理器、部分安装程序、某些安全软件）的按键。若用户需要在这些程序里划词，
  必须让 CtrlTranslator 也以管理员身份运行。
- **杀毒软件误报**：全局键盘钩子 + 模拟按键 + 剪贴板读取是键盘记录器的典型特征，
  可能被 Windows Defender 或国产安全软件拦截，需要用户手动加白名单。

## 3. 取词（剪贴板方案）

### 3.1 完整流程

```
1. 记录剪贴板序列号 seqBefore = GetClipboardSequenceNumber()
2. 备份当前剪贴板的 Unicode 文本（读不到就记为 null）
3. 确保物理修饰键已释放：
   若 GetAsyncKeyState 显示 Ctrl/Shift/Alt/Win 仍按下，
   用 SendInput 发送这些键的 KEYUP（避免和用户手指状态打架）
4. SendInput 发送：Ctrl↓ → C↓ → C↑ → Ctrl↑
5. 轮询：每 10ms 检查一次 GetClipboardSequenceNumber() != seqBefore，
   最多等 ClipboardWaitMs（默认 300ms）
6a. 序列号变了 → 读取剪贴板 Unicode 文本 = 取词结果
6b. 超时未变 → 判定为「没有选中文字」或「该程序不支持复制」→ 静默返回
7. 延迟 120ms 后，把备份的文本写回剪贴板（若备份为 null 则清空剪贴板）
   —— 延迟是为了避开目标程序自身对剪贴板的后续操作
```

### 3.2 剪贴板读写的健壮性要求

- 所有 `OpenClipboard` 调用失败时**重试 5 次，间隔 20ms**
- 不要用 `System.Windows.Clipboard.SetText()`（已知会随机抛 COM 异常），
  用 `Clipboard.SetDataObject(data, copy: true, retryTimes: 5, retryDelay: 20)`
  或自行 P/Invoke
- 备份/还原只处理 `CF_UNICODETEXT`。若原剪贴板内容是图片/文件列表，
  v1.0 接受"还原不了"，但必须**写日志记录一次**，不打扰用户

### 3.3 取词后的文本清洗

- 去掉首尾空白
- 若结果为空或纯空白 → 静默返回
- 若长度 > `LongTextThreshold`（默认 2000 字符）→ 弹出二次确认对话框：
  「你选中了 {n} 个字符，翻译它大约需要 {n/1000*X} 秒并消耗较多额度。确定要翻译吗？」
  按钮：`翻译` / `取消`
- 硬上限：> 20000 字符时直接拒绝，提示「选中内容过长（{n} 字符），
  请分段翻译。单次上限 20000 字符。」

### 3.4 词/句判定

去掉标点后按空白切分统计词数（中文按字符数 ≤ 4 视为词）：

- 词数 `<= WordThreshold`（默认 3）且不含句末标点 → **词典模式**
- 否则 → **翻译模式**

判定结果作为一个布尔量传给提示词构建器，见 §5.3。

## 4. 浮窗（PopupWindow）

### 4.1 窗口属性

```
WindowStyle        = None
AllowsTransparency = True
Background         = Transparent（内部 Border 才有实色背景）
ShowActivated      = False      ← 关键：不抢焦点，否则原程序会丢失选中状态
Topmost            = True
ShowInTaskbar      = False
ResizeMode         = CanResize
SizeToContent      = Height（宽度固定，高度自适应，但受 PopupMaxHeight 限制）
```

外观：圆角 8px、1px 边框、轻微投影、内边距 12px。
默认宽度 `PopupMaxWidth`（480 DIP），最大高度 `PopupMaxHeight`（400 DIP），
超出则译文区出现垂直滚动条。

### 4.2 定位算法

```
1. GetCursorPos() 取光标物理坐标 P
2. MonitorFromPoint(P) 取所在显示器，GetMonitorInfo 取工作区矩形 W（物理像素）
3. GetDpiForMonitor 取该显示器的 DPI 缩放 s
4. 期望位置 = P + (16, 20) * s     // 光标右下方
5. 若 期望右边界 > W.Right  → 改为 P.X - 窗口宽度 - 16*s（翻到光标左侧）
6. 若 期望下边界 > W.Bottom → 改为 P.Y - 窗口高度 - 20*s（翻到光标上方）
7. 最后钳制到 W 内，保证四边都不出屏
```

必须在 `app.manifest` 中声明 **Per-Monitor DPI Awareness V2**，
并在多显示器不同缩放比例（如主屏 150% + 副屏 100%）下位置与字号都正确。

### 4.3 关闭行为

| 动作 | 结果 |
|---|---|
| 按 `Esc` | 关闭 |
| 点击浮窗外部任意位置 | 关闭（除非已钉住） |
| 再次触发划词翻译 | 关闭旧浮窗，开新的 |
| 点击图钉按钮 | 切换钉住状态；钉住后点击外部**不关闭**，仅 Esc 和关闭按钮可关 |

> **实现要点**：因为 `ShowActivated = False`，窗口的 `Deactivated` 事件不可靠。
> 必须用低级鼠标钩子（`WH_MOUSE_LL`）监听 `WM_LBUTTONDOWN`，
> 判断点击点是否落在浮窗矩形之外，是则关闭。浮窗关闭时必须卸载鼠标钩子。

关闭浮窗时必须：停止朗读、取消进行中的翻译请求。

### 4.4 浮窗内容布局

```
┌────────────────────────────────────────┐
│  [🔊] [☆] [📋]              [📌] [✕]  │   ← 顶部工具条（高度 28）
├────────────────────────────────────────┤
│                                        │
│  译文内容区（可选中、可滚动）           │
│                                        │
└────────────────────────────────────────┘
```

| 元素 | 行为 |
|---|---|
| 🔊 朗读 | 朗读**原文**（见 §8）；朗读中图标变为停止态，再点则停止 |
| ☆ 收藏 | 切换星标；已收藏时图标实心 |
| 📋 复制 | 复制译文纯文本到剪贴板；成功后按钮短暂变为"已复制" |
| 📌 钉住 | 切换钉住状态 |
| ✕ 关闭 | 关闭浮窗 |
| 顶部工具条空白区 | 按住可拖动整个窗口 |

**翻译进行中**：工具条上的 🔊 ☆ 📋 置灰不可点，内容区显示加载动画 +
「翻译中…（已等待 2.3 秒）」的计时文字（每 100ms 刷新）。

**流式回退**：请求发出后 `StreamFallbackDelayMs`（默认 1500ms）内若已完整返回，
则一次性渲染；若超过该时间仍未完成，则**切换为逐块追加显示**，
且窗口高度增长时不要跳动（用 `MinHeight` 锁住已达到的高度）。

**主题**：跟随系统深/浅色（读注册表
`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`），
设置里可强制为浅色或深色。

### 4.5 词典模式的渲染

词典模式下 LLM 返回的是结构化纯文本（见 §5.3 提示词），按行渲染：

- 首行 `/音标/` → 用等宽字体、次要色
- 词性行 → 词性部分加粗
- 例句行 → 缩进、斜体、次要色

不要求解析成强类型对象，简单的按行前缀识别即可。

## 5. 翻译引擎

### 5.1 接口协议

`POST {BaseUrl}/chat/completions`，标准 OpenAI 格式。

- `BaseUrl` 由用户填写，形如 `https://api.deepseek.com/v1`
- 规范化处理：去掉末尾的 `/`；若用户填的地址末尾没有 `/v1` 且不含 `/v` 版本段，
  **不要自动补全**，而是在诊断中给出提示（不同服务商规则不一，自动补容易猜错）
- 请求头：`Authorization: Bearer {ApiKey}`、`Content-Type: application/json`
- 请求体：

```json
{
  "model": "{Model}",
  "messages": [
    {"role": "system", "content": "{构建出的系统提示词}"},
    {"role": "user",   "content": "{取到的原文}"}
  ],
  "temperature": 0.2,
  "max_tokens": 2048,
  "stream": true
}
```

**始终使用 `stream: true`**（即使 UI 默认攒完再显示），
这样才能测量首字延迟、支持超时判断、并支持 §4.4 的流式回退。

### 5.2 HttpClient 与连接预热

- 全局**单例** `HttpClient`，底层 `SocketsHttpHandler`：
  `PooledConnectionLifetime = 10min`、`PooledConnectionIdleTimeout = 5min`
- **启动预热**：应用启动 3 秒后（不阻塞启动），在后台向 `{BaseUrl}/models`
  发一个 GET 请求（失败也无所谓，目的只是建立 TLS 连接）
- **保活**：每 4 分钟重复一次预热，防止连接池空闲被回收
- 超时：整体 `RequestTimeoutSeconds`（默认 60s）；
  首字超时 `FirstTokenTimeoutSeconds`（默认 15s，从请求发出到收到第一个内容块）

### 5.3 提示词构建

系统提示词 = **当前模式的模板** + 运行时替换占位符。

占位符：

| 占位符 | 替换为 |
|---|---|
| `{target_lang}` | 目标语言（见 §5.4） |
| `{fallback_lang}` | 设置里的 `FallbackLanguage`（默认「英语」） |

模式模板中已内置词典模式的说明，因此**不需要**在运行时切换不同模板；
但为了提高判定准确度，当 §3.4 判定为词典模式时，
在 user 消息前追加一行标记：`[请按词典条目格式输出]\n`。

### 5.4 语言方向（自动互译）

1. 判定原文主要语言：统计字符集比例。
   中文字符（CJK 统一表意文字区）占比 > 20% → 判为中文；否则判为非中文。
2. 若原文为中文 → 目标语言 = `FallbackLanguage`（默认「英语」）
3. 若原文非中文 → 目标语言 = `TargetLanguage`（默认「中文」）

判定只用于填充 `{target_lang}` 占位符，最终由模型执行；
模板中已写明「若原文本身已是目标语言则译成 {fallback_lang}」作为兜底。

### 5.5 内置翻译模式（四个，用户可增删改）

模式在设置中管理，每个模式有 `Id`（不可改）、`Name`、`SystemPromptTemplate`。
内置模式可编辑但不可删除，并提供「恢复默认」按钮。

#### 模式 1 · `auto` —— 通用（默认选中）

```
你是一个精准的翻译引擎。将用户提供的文本翻译成{target_lang}。

规则：
1. 只输出译文本身，不要任何解释、前言、引号，也不要"译文："之类的标签。
2. 保留原文的段落结构与换行。
3. 人名、机构名、产品名、代码标识符、URL、数字、单位保持原样。
4. 若原文本身已是{target_lang}，则输出{fallback_lang}的译文。
5. 若输入是 1-3 个单词或一个不构成完整句子的短语，改为输出词典条目，严格用这个格式：
/音标/
词性. 释义1；释义2；释义3
例：一个英文例句 —— 该例句的中文翻译
6. 无意义的乱码或纯符号，原样返回，不要试图翻译。
```

#### 模式 2 · `academic` —— 学术科研

```
你是学术文献翻译专家，服务于中文母语的研究者。将文本翻译成{target_lang}。

规则：
1. 只输出译文本身，不要任何解释或标签。
2. 术语必须准确，采用该学科通行译法。关键术语首次出现时用「中文译名（English Original）」格式。
3. 英文长句必须拆成中文短句，符合中文表达习惯，不要保留英文的从句嵌套结构。
4. 保持学术书面语，不口语化，不加语气词，不加"我们可以看到"这类原文没有的填充语。
5. 以下内容原样保留，绝不翻译：LaTeX 公式与命令、数学符号、变量名、
   参考文献编号（如 [12]、(Smith et al., 2020)）、图表编号（Figure 3、Table 1）、DOI、URL、代码片段。
6. 被动语态按中文习惯转为主动，除非原文刻意强调受事。
7. 若原文本身已是{target_lang}，则输出{fallback_lang}的译文，并采用该语言的学术写作规范。
8. 若输入是 1-3 个单词或短语，改为输出词典条目，严格用这个格式：
/音标/
词性. 释义1；释义2；释义3   ← 优先给出该词在学术语境下的义项
例：一个学术语境的英文例句 —— 该例句的中文翻译
```

#### 模式 3 · `social` —— 社交媒体与网页

```
你是中文母语者的日常翻译助手。将文本翻译成{target_lang}。

规则：
1. 只输出译文本身，不要解释。
2. 用自然、口语化的中文，像人说话，绝不要翻译腔。
3. 网络用语、缩写、梗（lol、tbh、fr、ngl、IMO 等）译成对应的中文网络表达；
   实在没有对应的就意译，不要直译。
4. 保留 emoji、@提及、#话题标签 的原位置和原样。
5. 语气必须对：讽刺就是讽刺，玩笑就是玩笑，抱怨就是抱怨，不要译得一本正经。
6. 若原文本身已是{target_lang}，则输出{fallback_lang}的译文。
7. 若输入是 1-3 个单词或短语，改为输出词典条目，严格用这个格式：
/音标/
词性. 释义1；释义2；释义3
例：一个口语化的英文例句 —— 该例句的中文翻译
```

#### 模式 4 · `business` —— 办公邮件与商务

```
你是商务文书翻译助手。将文本翻译成{target_lang}。

规则：
1. 只输出译文本身，不要解释。
2. 用得体的书面语，措辞专业、简洁、礼貌，不啰嗦。
3. 中译英时：采用商务英语惯用表达，避免中式英语；
   称呼、敬语、结束语按英文商务信函习惯处理（如 Dear... / Best regards）。
4. 英译中时：不要逐字直译英文客套话，用中文商务场景里自然的说法。
5. 公司名、职位名、产品名、金额、日期、合同编号保持原样或采用通行译法。
6. 若原文本身已是{target_lang}，则输出{fallback_lang}的译文。
7. 若输入是 1-3 个单词或短语，改为输出词典条目，严格用这个格式：
/音标/
词性. 释义1；释义2；释义3   ← 优先给出商务语境下的义项
例：一个商务语境的英文例句 —— 该例句的中文翻译
```

### 5.6 推理模型检测（重要）

推理模型（会先长时间"思考"）不适合翻译，必须检测并警告用户。

**三重检测**：

1. **模型名匹配**（不区分大小写，正则）：
   `(^|[-_/])(r1|o1|o3|o4|qwq|reasoner|thinking|reasoning)([-_/]|$)`
2. **响应字段**：流式响应的 delta 中出现 `reasoning_content` 或 `reasoning` 字段
3. **首字延迟**：首字延迟 > 5000ms

命中任一项，在浮窗底部显示一条可关闭的黄色提示条：

> ⚠️ 你配置的模型「{model}」像是推理模型，它会先思考很久才输出，不适合划词翻译。
> 建议换成快速模型。[去设置] [不再提示]

「不再提示」写入设置 `SuppressReasoningWarning = true`。

### 5.7 推荐模型清单（用于引导向导和设置页的提示文字）

引导向导内置以下服务商预设（仅填入 Base URL 和推荐模型名，Key 由用户自己粘贴）：

| 服务商 | Base URL | 推荐模型（快） |

## 6. 缓存与数据存储

### 6.1 位置

```
%APPDATA%\CtrlTranslator\
├─ settings.json          # 配置（ApiKey 字段为 DPAPI 密文的 Base64）
├─ history.db             # SQLite
└─ logs\
   └─ ctrltranslator-yyyyMMdd.log
```

### 6.2 数据库结构

```sql
CREATE TABLE IF NOT EXISTS translations (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  cache_key    TEXT    NOT NULL,
  source_text  TEXT    NOT NULL,
  result_text  TEXT    NOT NULL,
  target_lang  TEXT    NOT NULL,
  mode_id      TEXT    NOT NULL,
  model        TEXT    NOT NULL,
  is_word      INTEGER NOT NULL DEFAULT 0,
  starred      INTEGER NOT NULL DEFAULT 0,
  app_name     TEXT,
  latency_ms   INTEGER,
  created_at   TEXT    NOT NULL   -- ISO 8601，本地时间
);

CREATE INDEX IF NOT EXISTS idx_cache_key ON translations(cache_key);
CREATE INDEX IF NOT EXISTS idx_starred   ON translations(starred, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_created   ON translations(created_at DESC);
```

### 6.3 缓存规则

`cache_key = SHA256(source_text + "" + target_lang + "" + mode_id + "" + model)`
取十六进制小写字符串。

**查询**：翻译开始前先按 `cache_key` 查最新一条。命中则：

- 立即渲染结果（0ms，不发网络请求）
- 日志记录 `cache hit`
- **不**新增数据库记录（但更新该条的 `created_at`，使其在历史里排到最前）

**写入**：翻译成功后插入一条新记录。
隐私模式（`PrivacyMode == true`）开启时**既不查缓存也不写库**。

### 6.4 主窗口（历史与收藏）

两个页签：**全部历史** / **我的收藏**。

列表每行显示：原文（截断至 60 字）· 译文（截断至 80 字）· 模式 · 时间 · 星标图标。

功能：

- 顶部搜索框，对 `source_text` 和 `result_text` 做 `LIKE %kw%` 搜索（实时，输入停顿 300ms 后触发）
- 选中一行，下方显示完整原文与译文（可复制）
- 右键菜单：复制原文 / 复制译文 / 切换星标 / 删除本条
- 底部按钮：**导出 CSV**
- 分页或虚拟化：一次最多加载 500 条，滚动到底加载更多

**CSV 导出规格**（必须能被 Excel 正确打开中文）：

- 编码：**UTF-8 with BOM**
- 列：`时间,模式,模型,原文,译文,已收藏,来源程序,耗时毫秒`
- 字段内的 `"` 转义为 `""`，含逗号/换行/引号的字段整体加引号
- 文件名：`CtrlTranslator-历史-yyyyMMdd-HHmmss.csv`，弹保存对话框

### 7.6 配置文件与密钥保护

- `settings.json` 用 `System.Text.Json` 序列化，缩进格式，UTF-8

- 读取时 `Unprotect`；解密失败（例如配置文件从别的机器拷来）时：
  当作未配置处理，写日志，并提示用户「密钥无法解密（可能是从其他电脑或其他 Windows 账户拷贝过来的），请重新填写」
- 配置文件写入用「写临时文件 → 原子替换」，避免写一半断电导致配置损坏
- 配置文件损坏无法解析时：自动备份为 `settings.json.bak`，用默认配置重建，并提示用户

## 8. 朗读（TTS）

- 使用 `System.Speech.Synthesis.SpeechSynthesizer`（SAPI 5）
- 朗读的是**原文**，不是译文
- 根据原文语言选择语音：优先选 `Culture` 匹配的已安装语音；
  英文优先选名字含 `Zira` / `David` / `Mark` 的；找不到匹配语音则用默认语音
- **无可用语音时**：按钮置灰，鼠标悬停提示
  「系统里没有安装可用的语音包。可到 Windows 设置 → 时间和语言 → 语音 → 添加语音 安装。」
- 朗读为异步（`SpeakAsync`），朗读中再次点击则 `SpeakAsyncCancelAll()` 停止
- **浮窗关闭时必须停止朗读**
- `SpeechSynthesizer` 使用单例并在应用退出时 `Dispose`

## 9. 错误处理与人话提示

### 9.1 错误映射表（必须完整实现）

| 判定条件 | 显示给用户的文字 | 操作按钮 |
|---|---|---|
| `BaseUrl` 或 `ApiKey` 或 `Model` 为空 | 还没配置翻译服务，点下面的按钮花一分钟设置好就能用了。 | `去设置` |
| `BaseUrl` 不以 `http://` 或 `https://` 开头 | 服务地址格式不对。正确的样子像这样：`https://api.deepseek.com/v1` | `去设置` |
| HTTP 401 / 403 | API Key 无效或已过期。请检查是不是填错了、或者前后多了空格。 | `去设置` |
| HTTP 402，或响应体含 `insufficient`/`balance`/`quota` | 账户余额不足或额度已用完，需要到服务商网站充值。 | `去设置` |
| HTTP 404，或响应体含 `model` 且含 `not found`/`does not exist` | 模型名「{model}」在这个服务商不存在。点「去设置」里的「拉取可用模型」看看有哪些能用。 | `去设置` |
| HTTP 429 | 请求太频繁被限流了，等几秒钟再试一次。 | `重试` |
| HTTP 5xx | 服务商那边出问题了（错误码 {code}），不是你的配置问题，过一会儿再试。 | `重试` |
| `HttpRequestException` / `SocketException` / DNS 失败 | 连不上服务器。检查一下网络；如果这个服务需要代理，请确认代理已开启。 | `一键诊断` |
| 首字超时 | 等了 {n} 秒还没有任何回应。可能网络很慢，也可能你填的是「推理模型」——那种模型会先思考很久，不适合用来划词翻译。 | `一键诊断` |
| 整体超时 | 翻译超时（{n} 秒）。文本可能太长，或者网络不稳定。 | `重试` |
| JSON 解析失败 | 服务器返回了看不懂的内容，这个地址可能不是 OpenAI 兼容接口。 | `一键诊断` |
| 剪贴板打开失败（重试后仍失败） | 剪贴板正被其他程序占用，稍等一下再试。 | — |
| 取词超时（未选中文字） | 静默，不打扰用户 | — |
| 数据库读写失败 | 历史记录保存失败，但翻译结果不受影响。详情见日志。 | `打开日志` |

### 9.2 展示位置

> ⚠️ **重要前提：不得依赖托盘气泡送达任何必须让用户看到的信息。**
> 本机用户已在 Windows 中全局关闭通知（`HKCU\...\PushNotifications\ToastEnabled = 0`），
> `NotifyIcon.ShowBalloonTip` 在这种情况下**静默失败、不报错、什么都不显示**。
> 气泡只作为"有则更好"的补充，所有关键信息必须另有可靠通道。

- 翻译相关的错误：显示在**浮窗内容区**，红色图标 + 文字 + 操作按钮
- 后台错误（数据库、日志、预热）：只写日志，不打扰用户
- 严重启动错误（无法创建数据目录、配置无法读写等）：
  用 **`MessageBox`** 显示（模态、必定可见）+ 写日志。**不要用气泡。**
- 一般性成功提示（取词成功、已复制等）：可以用气泡，但**必须同时**在界面上有
  非气泡的反馈（按钮变文字、状态栏、窗口内提示），不能只靠气泡

### 9.3 全局异常兜底

`App.xaml.cs` 中挂 `DispatcherUnhandledException`、`AppDomain.CurrentDomain.UnhandledException`、
`TaskScheduler.UnobservedTaskException`。捕获后：

1. 写完整日志
2. **本次运行的第一次**未处理异常：弹 `MessageBox` 显示
   「程序遇到了意外错误，已记录到日志。如果反复出现，请把日志发给开发者。」
   并附「打开日志文件夹」按钮
3. **之后的异常不再弹框**（避免异常风暴把屏幕刷满），改为把托盘图标切换到
   **警告态**，悬停提示变为 `CtrlTranslator — 出现过错误，请查看日志`，
   点击托盘图标可打开日志文件夹
4. 尽可能不退出程序（`e.Handled = true`）

## 10. 一键诊断

设置页「翻译服务」中的按钮，点击后弹出诊断窗口，**逐项执行并实时显示结果**，
每项显示 ✓ / ✗ / ⚠ + 耗时 + 说明文字。

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 配置完整性 | Base URL / Key / Model 三项都非空 |
| 2 | 地址格式 | 以 http(s):// 开头；若不含版本段（如 `/v1`）给 ⚠ 提示 |
| 3 | DNS 解析 | 能解析出主机 IP |
| 4 | 网络连通 | 能完成 TCP + TLS 握手（记录耗时） |
| 5 | 身份认证 | GET `/models` 返回 200；若返回 404 则跳过此项，改由第 6 项验证 |
| 6 | 模型可用性 | 发一个 `max_tokens: 1` 的最小翻译请求，返回 200 |
| 7 | 实测翻译 | 翻译固定句 `Hello, world.`，记录**首字延迟**和**总耗时** |
| 8 | 推理模型检测 | 模型名不匹配推理模型正则，且首字延迟 < 5s，且响应无 reasoning 字段 |
| 9 | 语音引擎 | 系统中至少有一个可用 SAPI 语音；有英语语音则额外 ✓ |
| 10 | 数据库 | 能打开 `history.db` 并完成一次写入-读取-删除 |
| 11 | 键盘钩子 | 钩子已成功安装（`SetWindowsHookEx` 返回非零），且划词未被暂停 |
| 12 | 运行权限 | 报告当前是否管理员；非管理员时给 ⚠ 说明 UIPI 限制 |

诊断窗口底部：**「复制诊断报告」**按钮，把全部结果复制为纯文本
（Key 必须脱敏为 `sk-****1234` 形式），方便用户粘给 AI 求助。

## 14. 打包与发布

```powershell
dotnet publish src/CtrlTranslator/CtrlTranslator.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -o publish
```

- **`PublishTrimmed` 必须为 false**（WPF 不支持裁剪）
- SQLite 的原生库必须靠 `IncludeNativeLibrariesForSelfExtract` 打进单文件
- 产物：`publish\CtrlTranslator.exe`，单文件，双击即可运行，无需安装 .NET
- 在仓库根提供 `build.ps1`，内容就是上面这条命令 + 完成后用资源管理器打开 `publish` 目录
- exe 需带图标和文件版本信息（`ApplicationIcon`、`AssemblyVersion`、`FileVersion`、
  `Product = CtrlTranslator`）

### README.md 必须包含

1. 一句话介绍 + 使用方法（选中文字 → 双击 Ctrl）
2. 首次使用：去哪申请 API Key、怎么填
3. **「找不到托盘图标？」一节** —— Windows 默认把新出现的托盘图标折叠进任务栏的
   `^` 箭头里（`EnableAutoTray` 默认为 1），首次运行看不到图标是正常现象。
   告诉用户：点 `^` 展开就能看到，把图标拖到任务栏上即可固定显示；
   或走「设置 → 个性化 → 任务栏 → 选择哪些图标显示在任务栏上」打开它。
   同时说明：即使图标折叠着，气泡提示仍会正常弹出。
