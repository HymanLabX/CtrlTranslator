# CtrlTranslator v1.0 需求规格书

> 唯一事实来源。实现时如与本文档冲突，以本文档为准。
> 本文档只描述 v1.0 范围内的需求；§13 列出的功能**明确不做**。

---

## 1. 产品定义

Windows 桌面常驻小工具。用户在**任意程序**中选中文字后**快速双击 Ctrl 键**，
鼠标附近弹出浮窗显示译文。翻译由用户自备的 OpenAI 兼容大模型接口完成。

- 无主界面常驻，只有系统托盘图标
- 典型使用场景：读英文学术论文、看外文网页新闻、写商务邮件
- 目标延迟：短句从双击到出结果 **1 秒内**（缓存命中时 0ms）

---

## 2. 触发机制

### 2.1 双击检测算法

使用低级键盘钩子 `SetWindowsHookEx(WH_KEYBOARD_LL, ...)`，安装在**一条专用的钩子线程**上
（`Interop/HookThread.cs`，这条线程有自己的消息循环，钩子才能收到回调）。
浮窗的"点外面关闭"鼠标钩子（§4.3）也装在这条线程上。

> **2026-10 变更（负责人同意）**：原来写的是"安装在 WPF 主线程"。
> 低级钩子的回调由安装它的线程的消息循环执行，系统给每次回调的时间有上限
> （注册表 `LowLevelHooksTimeout`），Windows 7 起**超时一次就会悄悄卸掉钩子**，程序无从得知 ——
> 表现是双击 Ctrl 突然没反应，直到重启软件。主线程偶尔会卡（第一次打开主窗口、剪贴板被占用、
> 磁盘慢），只要卡顿时用户正好在打字或动鼠标，钩子就可能被撤掉。
> 专用线程上只跑钩子回调，永远不会超时。回调里的规矩（AGENTS.md §5.2）不变，
> 判定成立后通过 `Dispatcher.BeginInvoke` 投递到主线程。

**术语定义：一次「有效敲击」** = 触发键（默认 Ctrl，含左右 Ctrl）
按下 → 抬起的一个完整周期，且满足：

1. 按下到抬起的时长 `< MaxKeyHoldMs`（默认 400ms）—— 排除长按
2. 从按下到抬起期间，**没有任何其他按键的 KEYDOWN 事件**
   —— 这是排除 `Ctrl+C`、`Ctrl+V`、`Ctrl+A` 等组合键的关键
3. 期间没有鼠标点击

**触发条件**：连续两次有效敲击，且第二次的抬起时刻与第一次的抬起时刻之差
`< DoubleTapIntervalMs`（默认 350ms）。

**触发后立即重置状态机**，使得连按三下只触发一次，不会触发两次。

**状态机字段**（全部为简单值类型，无锁访问）：

```
long  _lastTapReleaseTicks   // 上一次有效敲击的抬起时间戳
long  _currentPressTicks     // 本次按下的时间戳，0 表示当前未按下
bool  _pollutedByOtherKey    // 本次按下期间是否出现了其他键
```

**处理逻辑**：

| 事件 | 动作 |
|---|---|
| 触发键 KEYDOWN（且 `_currentPressTicks == 0`）| 记录 `_currentPressTicks = now`，`_pollutedByOtherKey = false` |
| 触发键 KEYDOWN（重复，来自键盘自动重复）| 忽略 |
| 其他键 KEYDOWN | `_pollutedByOtherKey = true` |
| 触发键 KEYUP | 计算是否为有效敲击 → 判定是否触发 → 重置 `_currentPressTicks = 0` |

> **实现要点**：Windows 的按住不放会产生连续 KEYDOWN，必须靠 `_currentPressTicks != 0`
> 去重，否则长按会被误判成连续敲击。

### 2.2 触发后的前置检查（按顺序，任一不通过则静默返回）

1. 全局暂停开关是否打开（`AppState.Enabled == false` → 返回）
2. 上一次触发距今 `< 500ms` → 返回（防抖）
3. 前台窗口是 CtrlTranslator 自己的窗口 → 返回

> 这里原本还有一项「进程名在应用黑名单中则返回」。**应用黑名单功能已删除**，
> 前台进程名仍然会取，但只用于写进历史记录的「来源程序」。

### 2.3 已知限制（必须在 README 和"关于"页面里向用户说明）

- **UIPI 限制**：以普通权限运行时，钩子收不到以管理员权限运行的程序
  （任务管理器、部分安装程序、某些安全软件）的按键。若用户需要在这些程序里划词，
  必须让 CtrlTranslator 也以管理员身份运行。
- **杀毒软件误报**：全局键盘钩子 + 模拟按键 + 剪贴板读取是键盘记录器的典型特征，
  可能被 Windows Defender 或国产安全软件拦截，需要用户手动加白名单。

## 3. 取词（剪贴板方案）

### 3.1 完整流程

```
1. 完整备份当前剪贴板（见 §3.2：文字、带格式文字、图片、文件列表……全部原样复制）
2. 记录剪贴板序列号 seqBefore = GetClipboardSequenceNumber()
   ⚠️ 必须放在备份之后：备份时原程序为"延迟渲染"的格式现场生成内容，也会让序列号变化，
   记早了会把这次变化误当成"复制成功"，读到的是旧剪贴板里的东西
3. 确保物理修饰键已释放：
   若 GetAsyncKeyState 显示 Ctrl/Shift/Alt/Win 仍按下，
   用 SendInput 发送这些键的 KEYUP（避免和用户手指状态打架）
4. SendInput 发送：Ctrl↓ → C↓ → C↑ → Ctrl↑
5. 轮询：每 10ms 检查一次 GetClipboardSequenceNumber() != seqBefore，
   最多等 ClipboardWaitMs（默认 300ms）
6a. 序列号变了 → 再等文字格式到位（最多 200ms：有的程序先清空剪贴板、再分几次放格式，
    文字不一定第一个到）→ 读取剪贴板 Unicode 文本 = 取词结果
6b. 超时未变 → 判定为「没有选中文字」或「该程序不支持复制」→ 静默返回（剪贴板没被动过，无需还原）
7. 延迟 120ms 后，把第 1 步的完整备份原样写回剪贴板（备份为空则清空剪贴板）
   —— 延迟是为了避开目标程序自身对剪贴板的后续操作
```

### 3.2 剪贴板读写的健壮性要求

所有剪贴板读写统一走 `Core/ClipboardService.cs`（直接调 Win32 剪贴板接口）：

- 所有 `OpenClipboard` 调用失败时**重试 5 次，间隔 20ms**，全部失败才报错
- 读写在线程池里同步完成（打开、读写、关闭必须在同一线程），不占界面线程
- **禁止**用 WPF 的 `Clipboard.SetText()`（已知会随机抛 COM 异常）和 `Clipboard.GetDataObject()`
  （内部会 `Thread.Sleep(100)` 重试 10 次，在界面线程上一卡就是一秒）。各处「复制」按钮也一样走 `ClipboardService`
- **完整备份与还原**（2026-10 变更，负责人同意）：原来只备份还原 `CF_UNICODETEXT`，
  实际使用 17 天约 70 次划词里有 6 次把用户剪贴板里的截图或文件清掉了。现在：
  - 剪贴板上所有"内存块"类型的格式原样复制（文字、RTF、HTML、DIB 图片、PNG、文件列表……）
  - 跳过 GDI 句柄类格式（`CF_BITMAP`、`CF_ENHMETAFILE`、`CF_METAFILEPICT`、`CF_PALETTE` 及私有/GDI 句柄区间）——
    它们复制字节没有意义；位图会被系统同时提供成 DIB，所以截图照样能还原
  - 总量上限 128MB、读取最多花 2 秒；超出的格式跳过并**写一次日志**，不打扰用户
  - 实测：4K 截图（约 63MB）备份 + 还原共约 150ms

### 3.3 取词后的文本清洗

- 去掉首尾空白
- 若结果为空或纯空白 → 静默返回
- 若长度 > `LongTextThreshold`（默认 2000 字符）→ 弹出二次确认对话框：
  「你选中了 {n} 个字符，翻译它大约需要 {n/1000*X} 秒并消耗较多额度。确定要翻译吗？」
  按钮：`翻译` / `取消`
- 硬上限：> 20000 字符时直接拒绝，提示「选中内容过长（{n} 字符），
  请分段翻译。单次上限 20000 字符。」
- 超过 2000 字的长文本，等待上限和输出上限会按长度放宽，见 §5.2「长文本」

### 3.4 词/句判定

先剥掉首尾的空白、引号、括号、逗号、分号、冒号（选区边界顺带进来的），
再去掉标点后按空白切分统计词数（中文按字符数 ≤ 4 视为词）：

- 词数 `<= WordThreshold`（默认 3）且不含句末标点 → **词典模式**
- 否则 → **翻译模式**

细则（2026-10 补充，都是实测踩出来的）：

- **一个英文词 + 结尾句点**（`heterogeneity.`，PDF 里双击常带上句号）→ 剥掉句点，按词处理
- **几个词 + 结尾句点**（`Hello, world.`、`I love you.`）→ 这是一句完整的话，按句子翻译
- 中间的英文句点只有后面跟空白才算断句：`e.g.`、`U.S.` 仍按词处理
- 结尾的问号、叹号不剥：`Really?` 是一句问话，给译文
- 中文的「。」不剥，按原规则处理
- 一个字母都没有（纯数字、纯符号，如 `3.14`）→ 不是词

判定结果作为一个布尔量传给提示词构建器，见 §5.3。

> ⚠️ **这个判定是唯一的判定者，模型不得自行判断（已踩坑）**
>
> 词典格式**只能**由 `[请按词典条目格式输出]` 这个标记触发，标记由代码按上面的词数规则添加。
>
> 提示词里**绝不允许**出现「若输入是 1-3 个单词**或短语**」「不构成完整句子时」
> 这类让模型自己判断的措辞。曾经这么写过，后果是：
> 划取 `demonstrating progressive loop stabilization`（4 词，超过阈值，代码判定为句子、
> 没加标记），模型看到"或短语"就自作主张按词典格式输出了音标 + 词性 + 两个候选释义。
> 用户要的只是一句译文。
>
> 同时，提示词必须**正面**写清楚：划取的常常是文档里的片段（短语、动名词结构、从句、半句话），
> 这种情况照样只给一句译文，不注音标、不标词性、不用「；」罗列多个候选。
> 只删掉"或短语"是不够的——不写这条，模型仍会倾向于对不完整的片段做语法分析。

## 4. 浮窗（PopupWindow）

### 4.1 窗口属性

```
WindowStyle        = None
AllowsTransparency = True
Background         = Transparent（内部 Border 才有实色背景）
ShowActivated      = False      ← 关键：不抢焦点，否则原程序会丢失选中状态
Topmost            = True
ShowInTaskbar      = False
ResizeMode         = CanResize
SizeToContent      = Height（宽度固定，高度自适应，但受 PopupMaxHeight 限制）
```

外观以 `DESIGN.md` §5.5 为准（圆角 14px、1px 外框、投影）。
默认宽度 `PopupMaxWidth`（480 DIP），最大高度 `PopupMaxHeight`（400 DIP），
超出则译文区出现垂直滚动条。宽高与字号由设置页的预设决定（§7.1）。

### 4.2 定位算法

```
1. GetCursorPos() 取光标物理坐标 P
2. MonitorFromPoint(P) 取所在显示器，GetMonitorInfo 取工作区矩形 W（物理像素）
3. GetDpiForMonitor 取该显示器的 DPI 缩放 s
4. 期望位置 = P + (16, 20) * s     // 光标右下方
5. 若 期望右边界 > W.Right  → 改为 P.X - 窗口宽度 - 16*s（翻到光标左侧）
6. 若 期望下边界 > W.Bottom → 改为 P.Y - 窗口高度 - 20*s（翻到光标上方）
7. 最后钳制到 W 内，保证四边都不出屏
```

必须在 `app.manifest` 中声明 **Per-Monitor DPI Awareness V2**，
并在多显示器不同缩放比例（如主屏 150% + 副屏 100%）下位置与字号都正确。

### 4.3 关闭行为

| 动作 | 结果 |
|---|---|
| 按 `Esc` | 关闭 |
| 点击浮窗外部任意位置 | 关闭（除非已钉住） |
| 再次触发划词翻译 | 关闭旧浮窗，开新的 |
| 点击图钉按钮 | 切换钉住状态；钉住后点击外部**不关闭**，仅 Esc 和关闭按钮可关 |

> **实现要点**：因为 `ShowActivated = False`，窗口的 `Deactivated` 事件不可靠。
> 必须用低级鼠标钩子（`WH_MOUSE_LL`）监听 `WM_LBUTTONDOWN`，
> 判断点击点是否落在浮窗矩形之外，是则关闭。浮窗关闭时必须卸载鼠标钩子。
> 这个鼠标钩子和键盘钩子一样装在专用钩子线程上（§2.1），否则主线程一卡，
> 它会被系统悄悄撤掉，表现是"点浮窗外面不关了"。

> ⚠️ **边界必须在原生窗口真正 resize 之后再刷新（已踩坑）**
> WPF 的 `SizeChanged` 在**布局阶段**触发，而原生窗口的 `SetWindowPos` 发生在**之后**。
> 若此时调用 `GetWindowRect`，拿到的是**变化前的旧矩形**。
> 配合 `SizeToContent="Height"`，窗口内容变高（例如底部弹出警告条）后，
> 新增的那一条区域会被判定为"窗外" —— 用户点上面的按钮时浮窗直接关闭，
> **按钮永远收不到点击**，且不产生任何日志，极难排查。
>
> 要求：
> 1. 边界刷新必须排到布局完成之后，例如
>    `Dispatcher.BeginInvoke(RefreshPhysicalBounds, DispatcherPriority.Loaded)`，
>    或监听原生 `WM_WINDOWPOSCHANGED` 消息
> 2. 兜底：`ClickedOutside` 真正执行关闭**之前**，重新 `GetWindowRect` 复核一次，
>    确认点击点确实在窗外才关。这一步很便宜，但能挡住所有同类时序问题

关闭浮窗时必须：停止朗读、取消进行中的翻译请求。

### 4.4 浮窗内容布局

> UI 改版后的布局（详细尺寸见 `DESIGN.md` §5.5）：

```
┌────────────────────────────────────────┐
│  原文回显（掐头留尾）         [📌] [✕]  │   ← 顶行：确认划的是不是这段 + 窗口控制
│  [提示条：截断 / 推理模型 / 错误]        │   ← 默认隐藏
│  小字：已自动改用备用 / 代理没开已直连    │   ← 默认隐藏
├────────────────────────────────────────┤
│  译文内容区（可选中、可滚动）            │
├────────────────────────────────────────┤
│  [🔊] [☆] [📋]          模型 · 0.6s     │   ← 对译文的操作 + 这次是谁翻的
└────────────────────────────────────────┘
```

| 元素 | 行为 |
|---|---|
| 🔊 朗读 | 朗读**原文**（见 §8）；朗读中图标变为停止态，再点则停止 |
| ☆ 收藏 | 切换星标；已收藏时图标实心 |
| 📋 复制 | 复制译文纯文本到剪贴板；成功后按钮短暂变为"已复制" |
| 📌 钉住 | 切换钉住状态 |
| ✕ 关闭 | 关闭浮窗 |
| 外壳空白处（内容区和按钮以外） | 按住可拖动整个窗口 |

**译文不完整要说出来**（2026-10 补充）：服务商报告 `finish_reason` 为 `length`（写到输出上限）
或 `content_filter`（被内容审核截停）时，提示条显示
「译文不完整：写到了「最大输出长度」上限（{n}）被截断了。可以在设置里调大。」+ `去设置`。
这种译文照样记进历史，但不会被缓存命中（见 §6.3）。

**代理没开时**（2026-10 补充）：翻译是自动直连完成的（§5.2），小字说明一句
「你设置的代理（127.0.0.1:7897）没开，这次已自动直连。」

> ⚠️ **拖动区必须显式设 `Background`（已踩坑）**
> WPF 中 `Background = null`（面板的默认值）的 `Grid` / `StackPanel`
> **不参与命中测试**，鼠标事件会直接穿过去，`MouseLeftButtonDown` 永远不触发，
> 且不产生任何日志、不抛异常，极难排查。
> 承载拖动的工具条容器必须写 `Background="Transparent"` —— 透明但可命中。
> 同理，任何靠自身空白区接收鼠标事件的面板都要这样处理。

**翻译进行中**：工具条上的 🔊 ☆ 📋 置灰不可点，内容区显示加载动画 +
「翻译中…（已等待 2.3 秒）」的计时文字（每 100ms 刷新）。

**流式回退**：请求发出后 `StreamFallbackDelayMs`（默认 1500ms）内若已完整返回，
则一次性渲染；若超过该时间仍未完成，则**切换为逐块追加显示**，
且窗口高度增长时不要跳动（用 `MinHeight` 锁住已达到的高度）。

**配色**：主窗口、设置页和向导只有一套浅色，不跟随系统深浅色。
**浮窗单独可选三套配色**（浅色 / 深色 / 护眼，§7.1），只作用于浮窗这一扇窗口，
实现与色值见 `DESIGN.md` §5.5。（M7 砍掉的是"跟随系统的全局深色主题"，浮窗配色是后来单独加的。）

### 4.5 词典模式的渲染

词典模式下 LLM 返回的是结构化纯文本（见 §5.3 提示词），由 `DictionaryEntryParser` 拆成
音标 / 义项 / 例句再排版：

- 音标行 → 等宽字体、次要色。认 `/…/`、`[…]`、`英 /…/ 美 /…/` 几种写法
- 义项行 → 词性加粗。词性只认长得像词性的东西（`n.`、`adj.`、`vt./vi.`、`名词`……），
  不再把"前 8 个字里出现句号"的中文释义误当成词性
- 例句 → 左侧竖线，例句与它的译文分两行

模型不守格式、什么结构都认不出来时，整段按普通译文显示，不能留空白。

## 5. 翻译引擎

### 5.1 接口协议

`POST {BaseUrl}/chat/completions`，标准 OpenAI 格式。

- `BaseUrl` 由用户填写，形如 `https://api.deepseek.com/v1`
- 规范化处理：去掉末尾的 `/`；若用户填的地址末尾没有 `/v1` 且不含 `/v` 版本段，
  **不要自动补全**，而是在诊断中给出提示（不同服务商规则不一，自动补容易猜错）
- 请求头：`Authorization: Bearer {ApiKey}`、`Content-Type: application/json`。
  **Key 为空时不发 `Authorization`**：本机服务（`localhost` / `127.x` / `::1`，如本地 Ollama）不需要 Key，
  这类地址允许不填 Key；其他地址不填 Key 仍按"还没配置翻译服务"处理
- 请求体：

```json
{
  "model": "{Model}",
  "messages": [
    {"role": "system", "content": "{构建出的系统提示词}"},
    {"role": "user",   "content": "{取到的原文}"}
  ],
  "temperature": 0.2,
  "max_tokens": 2048,
  "stream": true
}
```

**始终使用 `stream: true`**（即使 UI 默认攒完再显示），
这样才能测量首字延迟、支持超时判断、并支持 §4.4 的流式回退。

解析流式响应时还要处理两件事（2026-10 补充）：

- **流里的错误块**：有的服务商（聚合网关最常见）HTTP 200 已经回了，流到一半才发
  `data: {"error": {...}}`。必须按 API 错误处理（错误码取 `error.code` 里的数字，没有就按 502），
  再交给 §9.1 的分类，而不是当成空数据跳过、最后报"返回内容看不懂"
- **`finish_reason`**：记下最后一次出现的值。`length` / `content_filter` 说明译文不完整，见 §4.4

#### 额外请求参数（`ExtraRequestBody`）—— 关闭"思考模式"的通用机制

**背景（实测）**：DeepSeek V4 系列（`deepseek-v4-flash` / `deepseek-v4-pro`）的
`thinking` 参数**默认值是 `enabled`**。不显式关闭时，模型每次都会先长时间"思考"再输出译文。
实测翻一句话耗时约 **4 秒**（目标是 1 秒内），且思考产生的 token 按输出价计费，
用量可能翻十倍。**其他厂商也各有各的写法**，所以不能写死成某一家的开关。

机制：设置中提供一个 **`ExtraRequestBody`** 字段，内容是一段 JSON 对象。
构造请求时把它**浅合并**进请求体顶层；同名键以 `ExtraRequestBody` 为准（用户优先）。

- **默认值**：`{"thinking": {"type": "disabled"}}`
- 为空或解析失败时：跳过合并，写一条日志，**不要因此让翻译失败**
- 解析失败时在设置界面上给出红色提示「这段不是合法的 JSON，已忽略」

各厂商的关闭写法（用于 §7.2 的预设按钮）：

| 服务商 | 填入内容 |
|---|---|
| DeepSeek V4 / 智谱 GLM | `{"thinking": {"type": "disabled"}}` |
| 阿里通义千问 / 硅基流动 | `{"enable_thinking": false}` |
| OpenAI GPT-5 系列 | `{"reasoning_effort": "minimal"}` |
| 不需要 / 跟随服务商默认 | 留空 |

"思考模式关没关"的判断（§5.6 的提示条、§9.1 的首字超时规则①都依赖它）认上表全部写法，
外加 vLLM 的 `{"chat_template_kwargs": {"enable_thinking": false}}` 和
OpenRouter 的 `{"reasoning": {"effort": "minimal"}}` / `{"reasoning": {"enabled": false}}`。
（以前只认第一种：通义用户明明按预设关了思考，首字一超时却被告知"你的关闭思考模式开关关着"。）

### 5.2 HttpClient 与连接预热

- 全局**单例** `HttpClient`，底层 `SocketsHttpHandler`：
  `PooledConnectionLifetime = 10min`、`PooledConnectionIdleTimeout = 5min`、`ConnectTimeout = 10s`
- **启动预热**：应用启动 3 秒后（不阻塞启动），在后台向 `{BaseUrl}/models`
  发一个 GET 请求（失败也无所谓，目的只是建立 TLS 连接）
- **保活**：每 4 分钟重复一次预热，防止连接池空闲被回收
- **预热日志只在状态变化时写**（首次成功、成功↔失败、失败原因变了）。以前每 4 分钟写一行，
  实际日志里九成以上都是它，真正的问题被淹没

#### 系统代理没开时自动直连（2026-10 变更，负责人同意）

请求默认按 Windows 的系统代理设置走。**只有当系统代理的端口拒绝连接时**（典型场景：
代理软件退出了，但系统代理设置还留着），自动改为直连再发一次，并在浮窗上小字说明（§4.4）。

- 只认"端口拒绝连接"这一种（瞬间就能判定）；代理慢、代理返回错误都不绕开它
- 直连也失败时，报错点名代理：「你电脑上设置的代理（127.0.0.1:7897）没有打开，已经自动改为直连，
  但直连也连不上服务器……」
- 拉取模型列表、连接检测、连接预热走同一条路

#### 超时（硬性上限，产品决策）

**任何一次翻译从发出请求到译文输出完毕，总共不得超过 15 秒。** 超了就判失败并报错，
**不提供「继续等待」选项** —— 划词翻译等超过 15 秒，即使最后出来了也已经打断阅读节奏。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `RequestTimeoutSeconds` | **15** | 从发请求到全部输出完毕的硬上限 |
| `FirstTokenTimeoutSeconds` | **10** | 从发请求到收到第一个内容块 |

- 首字超时**必须小于**整体超时，设置页要做校验，否则首字超时永远不会先触发、
  两种失败就分不出来了
- 实测参考（关闭思考模式的 `deepseek-v4-flash`）：780 字的段落总耗时仅 2.4 秒，
  首字 0.4–0.9 秒。15 秒在正常情况下永远碰不到，真碰到就说明已经不正常了

#### 长文本（2026-10 变更，负责人同意）

15 秒上限是为"划一句话"定的。原文超过 **2000 字**（用户已在 §3.3 的确认框里点过「翻译」）时，
按长度放宽：

| 项 | 规则 |
|---|---|
| 整体超时 | 15 秒 + 每千字 6 秒（实测约 3 秒 / 千字，留两倍余量），**最多 120 秒** |
| 首字超时 | 不变 |
| 输出上限 | 取「档案设置」和「原文字数 × 1.2 + 256」中较大的，**最多 8192** |

- 放宽后的输出上限被服务商拒绝（有的家单次只给 4096）时，自动退回档案设置的值重试一次，
  不算这个档案的失败
- 原因：以前 2 万字的上限和 15 秒的上限互相矛盾 —— 超过约五千字必然超时，
  确认框还在说"大约需要 30 秒"

### 5.3 提示词构建

系统提示词 = **当前模式的模板**（只管翻译风格，不提任何语言）+ **程序生成的方向指令**（拼在最后）。

- 方向指令写死方向，不写条件句：原文是中文时「本次翻译方向：中文 → 英语。整段译文必须用英语书写。」；
  原文是外文时「本次翻译方向：外文 → 中文。……」。原文是外文时只写「外文」不写具体语种 ——
  方向判定只认得出"是不是中文"，以前一律写「英语 → 中文」，划一段法文、日文进来等于给了模型一句假话
- 方向指令必须拼在**最后**：放最前面会被后面整套风格规则盖过去，中译英会翻出中文（已实测）
- 老版本自定义提示词里的 `{target_lang}` / `{fallback_lang}` 占位符仍会被替换，作兼容
- 当 §3.4 判定为词典模式时，在 user 消息前追加一行标记：`[请按词典条目格式输出]\n`

### 5.4 语言方向（自动互译）

1. 判定原文主要文字（`Translation/TextLanguage.cs`）：
   - 含平假名 / 片假名（至少 2 个、且占汉字加假名的两成以上）→ 日文
   - 谚文占比 > 20% → 韩文
   - 汉字（CJK 统一表意文字区）占比 > 20% → 中文
   - 其他 → 外文
2. 原文是中文 → 目标语言 = `FallbackLanguage`（默认「英语」）
3. 原文不是中文（含日文、韩文）→ 目标语言 = `TargetLanguage`（默认「中文」）

> 2026-10 补充：以前只数汉字占比，日文里汉字常常占三四成，于是日文被当成中文、翻成了英语。
> 纯汉字写成的日文标题仍会被当成中文 —— 只看字符分不出来，属于已知边界。

### 5.5 内置翻译模式（四个，用户可增删改）

模式在设置中管理，每个模式有 `Id`（不可改）、`Name`、`SystemPromptTemplate`（划词浮窗用）、
`DeepPromptTemplate`（深度翻译页用，§15）。
内置模式可编辑但不可删除，并提供「恢复默认」按钮（两套提示词一起恢复）。

> **提示词全文以 `Settings/BuiltInModes.cs` 为准，本文件不再抄录**（2026-10 变更）。
> 以前这里抄了四段模板，代码改了几版之后早已对不上，还留着下面明令禁止的「或短语」写法 ——
> 照着本文件去改提示词只会把老坑改回来。四个模式的取向：
>
> | Id | 名称 | 取向 |
> |---|---|---|
> | `auto` | 通用 | 默认取舍，什么都能翻 |
> | `academic` | 学术科研 | 术语用学科通行译法、首次出现并列原文，公式与文献编号原样保留，长句按目标语言习惯拆分 |
> | `social` | 社交媒体 | 自然口语、网络用语意译、保留 emoji 与 @ #、语气要对 |
> | `business` | 办公邮件 | 得体书面语，中译英用商务惯用表达，英译中不直译客套话 |
>
> 四个模式共用两条规则：**片段规则**（划到半句话照样只给一句译文，不注音标、不罗列候选）
> 和**词典规则**（只有见到 §5.3 的标记才输出词典条目）。

> ⚠️ **提示词是持久化的，改代码对老用户不生效（已踩坑）**
>
> `Modes` 整个列表（含 `SystemPromptTemplate`）会被序列化进 `settings.json`。
> `Normalize()` 原先只按 `Id` 补齐缺失的内置模式，**不会更新已存在模式的提示词**——
> 也就是说改了 `BuiltInModes.cs` 里的提示词，已经用过软件的人还是跑旧提示词。
>
> 机制：`AppSettings.CurrentPromptVersion` + 配置里的 `PromptVersion`。
> 载入时若 `PromptVersion < CurrentPromptVersion`，把所有内置模式的
> `SystemPromptTemplate` 覆盖为代码里的最新版，然后写回配置文件。
> 自定义模式（`Id` 不在内置清单里）不受影响。
>
> **凡是改动 `BuiltInModes.cs` 里的提示词文字，必须同时把 `CurrentPromptVersion` 加一。**
> 忘了加，改动就是死的；而且缓存 key 也不会失效（见 §6.3），双重不生效。
>
> `PromptVersion` 属性**不能写默认值初始化器**。System.Text.Json 在 JSON 缺字段时
> 会保留对象的初始值，写了初始值等于老配置一载入就"已是最新版"，迁移永远不触发。

### 5.6 推理模型检测（重要）

推理模型（会先长时间"思考"）不适合翻译，必须检测并警告用户。

**三重检测**：

1. **模型名匹配**（不区分大小写，正则）：
   `(^|[-_/])(r1|o1|o3|o4|qwq|reasoner|thinking|reasoning)([-_/]|$)`
2. **响应字段**：流式响应的 delta 中出现 `reasoning_content` 或 `reasoning` 字段
3. **首字延迟**：首字延迟 > 5000ms

命中任一项，在浮窗底部显示一条可关闭的黄色提示条：

> ⚠️ 你配置的模型「{model}」正在"思考"，这会让翻译慢很多、也更费钱。
> [关闭思考模式] [去设置] [不再提示]

三个按钮的行为：

| 按钮 | 行为 |
|---|---|
| **关闭思考模式** | 按这个档案的服务商写入对应的关闭参数（合并进已有内容，不覆盖其他键）→ 保存设置 → **立刻用新参数重译当前这段文字** → 成功则提示条消失 |
| 去设置 | 打开设置的「翻译模型」页并定位到 `ExtraRequestBody` 字段 |
| 不再提示 | 写入 `SuppressReasoningWarning = true` |

> 「关闭思考模式」是给不懂技术的用户准备的一键自救 —— 他不需要知道什么是 JSON，
> 点一下就恢复正常速度。写哪个键按服务地址判断（2026-10 补充）：
> 通义（`dashscope.aliyuncs.com`）/ 硅基流动 → `{"enable_thinking": false}`；
> OpenAI（`api.openai.com`）→ `{"reasoning_effort": "minimal"}`；其余 → `{"thinking": {"type": "disabled"}}`。
> 改的是**这次真正出结果（或出错）的那个档案**，自动降级之后它不一定是当前档案。

## 6. 缓存与数据存储

### 6.1 位置

```
%APPDATA%\CtrlTranslator\
├─ settings.json          # 配置（ApiKey 字段为 DPAPI 密文的 Base64）
├─ history.db             # SQLite
└─ logs\
   └─ ctrltranslator-yyyyMMdd.log
```

### 6.2 数据库结构

```sql
CREATE TABLE IF NOT EXISTS translations (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  cache_key    TEXT    NOT NULL,
  source_text  TEXT    NOT NULL,
  result_text  TEXT    NOT NULL,
  target_lang  TEXT    NOT NULL,
  mode_id      TEXT    NOT NULL,
  model        TEXT    NOT NULL,
  is_word      INTEGER NOT NULL DEFAULT 0,
  starred      INTEGER NOT NULL DEFAULT 0,
  app_name     TEXT,
  latency_ms   INTEGER,
  created_at   TEXT    NOT NULL,  -- ISO 8601，本地时间；翻译真实发生的时刻，永不改写
  -- 以下四列为 M5 之后追加（老库启动时自动补列）
  profile_name      TEXT,         -- 实际翻出这条的档案
  prompt_tokens     INTEGER,      -- 服务商主动回报的用量，拿不到为 NULL
  completion_tokens INTEGER,
  last_used_at      TEXT          -- 最后一次被缓存命中的时间
);

CREATE INDEX IF NOT EXISTS idx_cache_key ON translations(cache_key);
CREATE INDEX IF NOT EXISTS idx_starred   ON translations(starred, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_created   ON translations(created_at DESC);
```

### 6.3 缓存规则

`cache_key = SHA256(原文、完整系统提示词、user 消息、目标语言、模式 Id、模型名、temperature、额外请求参数)`
（各项用控制字符 U+0001 拼接），取十六进制小写字符串。

> ⚠️ **所有会改变模型输出的输入都必须进 key（已踩坑）**
>
> 提示词一改，同一段原文该出的译文就变了。key 里不带它的话，
> 改完提示词再去划同一句话，命中的还是旧缓存里的旧格式结果，
> 看上去就像"改动根本没生效"——这个假象已经真实误导过一次排查。
>
> 早先的做法是 key 里放一个手工维护的 `prompt_version`，漏了两类改动：
> 用户在设置页直接改模式提示词（版本号不变），以及开发者改了提示词忘了加版本号。
> 现在直接哈希提示词全文，这两种情况都自动生效；temperature 和额外请求参数同样纳入。
> 旧记录不删除，只是不再被命中；历史记录和收藏完整保留。

**查询**：翻译开始前先按 `cache_key` 查最新一条。命中则：

- 立即渲染结果（0ms，不发网络请求）
- 日志记录 `cache hit`
- **不**新增数据库记录，只更新该条的 `last_used_at`。
  **`created_at` 永不改写**：它是这条翻译真实发生的时刻，历史排序、显示和 CSV 都以它为准
  （早先命中缓存会改写 `created_at`，三个月前翻的东西今天再划一次就显示成今天，真实时间被永久覆盖）

**写入**：翻译成功后插入一条新记录。
**不完整的译文**（§4.4，写到输出上限或被内容审核截停）照样写入历史，但 `cache_key` 加后缀 `#incomplete`，
永远不会被命中 —— 否则调大输出上限之后再划同一段，拿到的还是这份被截断的旧结果。
隐私模式（`PrivacyMode == true`）开启时**既不查缓存也不写库**。

**清空历史 / 清空缓存之后压实数据库文件**（`VACUUM`，2026-10 补充）：SQLite 删记录只是把页标成可复用，
原文译文的字节还躺在文件里，用工具打开照样翻得出来。用户点「清空」就是要它没了。

### 6.4 主窗口（深度翻译 / 应用设置 / 翻译历史）

> **UI 改版变更**：历史与设置并入同一个主窗口，左侧一级导航三项：
> **深度翻译**（§15）/ **应用设置**（§7）/ **翻译历史**。布局细节见 `DESIGN.md` §5。

翻译历史页：

- 「全部 / 已收藏」筛选（收藏是筛选条件，不占一级导航）
- 搜索框，对 `source_text` 和 `result_text` 做 `LIKE %kw%` 搜索（输入停顿 220ms 后触发）
- **单列卡片流**：每张卡上半原文、下半译文，折叠时各最多两行；点卡片展开完整内容和来源说明
  （模型 · 服务商 · 来自哪个程序 · 耗时），再点收起
- 卡片上直接操作：复制原文 / 收藏 / 删除（跟着原文那半边），复制译文（跟着译文那半边）。
  **删除即删，不二次确认；不提供右键菜单；每条不显示时间**（UI 改版时确认的简化）
- 一次最多加载 500 条，滚动到底加载更多
- 列表**就地更新**（2026-10 补充）：刚翻译完的新记录插到顶部、删除就地拿掉、浮窗上点收藏就地改星标，
  不再整表重载 —— 以前每翻译一次列表就跳回顶部，展开的卡片也收起了
- **CSV 导出**在「应用设置 → 关于」里，不占历史页

**CSV 导出规格**（必须能被 Excel 正确打开中文）：

### 7.5 配置文件与密钥保护

- `settings.json` 用 `System.Text.Json` 序列化，缩进格式，UTF-8
- `ApiKey` **不以明文存储**：用 `ProtectedData.Protect(bytes, null, DataProtectionScope.CurrentUser)`
  加密后转 Base64 存入 `ApiKeyProtected` 字段
- 读取时 `Unprotect`；解密失败（例如配置文件从别的机器拷来）时：
  当作未配置处理，写日志，并提示用户「密钥无法解密（可能是从其他电脑或其他 Windows 账户拷贝过来的），请重新填写」
- 配置文件写入用「写临时文件 → 原子替换」，避免写一半断电导致配置损坏
- 配置文件损坏无法解析时：自动备份为 `settings.json.bak`，用默认配置重建，并提示用户

## 9. 错误处理与人话提示

### 9.1 错误映射表（必须完整实现）

> **2026-10 变更**：HTTP 错误的归类由 `Translation/ApiErrorClassifier.cs` 统一判断，
> 浮窗报错（本表）和自动降级（§9.4）**共用这一份**。以前两边各写一套、早已分叉：
> 降级那边不再拿裸子串 `insufficient / balance / quota` 判余额，报错这边却还在用，
> 结果 `insufficient permissions`、`max_tokens exceeds the per-request quota` 这类参数错误
> 会被说成"余额不足，去充值"。判定顺序就是下表从上到下的顺序（余额排在鉴权前面：
> 硅基流动的余额不足是 403，智谱的欠费是 429，按状态码先判会说成"Key 无效""请求太频繁"）。

| 判定条件 | 显示给用户的文字 | 操作按钮 |
|---|---|---|
| `BaseUrl` 或 `Model` 为空，或（不是本机服务时）`ApiKey` 为空 | 还没配置翻译服务，点下面的按钮花一分钟设置好就能用了。 | `去设置` |
| `BaseUrl` 不以 `http://` 或 `https://` 开头 | 服务地址格式不对。正确的样子像这样：`https://api.deepseek.com/v1` | `去设置` |
| HTTP 402，或报文里有明确的余额说法（`insufficient balance`、`balance is insufficient`、`insufficient_quota`、`exceeded your current quota`、`Arrearage`、`欠费`、`余额不足`……） | 账户余额不足或额度已用完，需要到服务商网站充值。 | `去设置` |
| 报文说地区不支持（`unsupported_country_region_territory` 等） | 这个服务商不对你所在的地区开放。换一家国内服务商，或者开代理后再试。 | `去设置` |
| 报文说内容审核不通过（`content_filter`、`DataInspectionFailed`、`敏感内容`……） | 服务商的内容审核拒绝翻译这段文字。换一段文字，或者在设置里换一家服务商试试。 | — |
| 400 / 403 / 404 / 422 且报文说模型不存在（`model` + `not found` / `does not exist` / `not exist`，`model_not_found`，`模型不存在`） | 模型名「{model}」在这个服务商不存在。点「去设置」里的「拉取可用模型」看看有哪些能用。 | `去设置` |
| HTTP 401 / 403 | API Key 无效或已过期。请检查是不是填错了、或者前后多了空格。 | `去设置` |
| HTTP 404 / 405（报文没提模型） | 服务地址可能填错了：服务商说找不到这个接口（错误码 {code}）。对照服务商文档检查一下地址，通常以 /v1 之类的版本号结尾。 | `去设置` |
| HTTP 429 | 请求太频繁被限流了，等几秒钟再试一次。 | `重试` |
| HTTP 5xx | 服务商那边出问题了（错误码 {code}），不是你的配置问题，过一会儿再试。 | `重试` |
| 其余 4xx | 服务商拒绝了这次请求（错误码 {code}）。最常见的原因是「额外请求参数」里有它不认识的参数……服务商的原话：{原话，截短} | `去设置` |
| 系统代理端口拒绝连接、自动直连也失败（§5.2） | 你电脑上设置的代理（{地址}）没有打开，已经自动改为直连，但直连也连不上服务器…… | `一键诊断` |
| 代理开着但连不上服务商（CONNECT 失败） | 代理软件开着，但它连不上翻译服务。检查一下代理软件里的节点…… | `一键诊断` |
| TLS 握手失败 | 和服务器的加密连接没有建立成功。常见原因是代理软件或公司网络拦截了 HTTPS，或者电脑的系统时间不对…… | `一键诊断` |
| 域名解析失败 | 找不到服务器（域名解析失败）。检查一下网络是否连上，以及服务地址有没有拼错。 | `一键诊断` |
| 其余 `HttpRequestException` / `SocketException` | 连不上服务器。检查一下网络；如果这个服务需要代理，请确认代理已开启。 | `一键诊断` |
| ①首字超时**且**「关闭思考模式」当前**未开启** | **翻译超时了（等了 {n} 秒）。原因是你的「关闭思考模式」开关关着，模型会先思考很久再回答，而本软件的上限是 15 秒。想用思考模式的话，它基本不适合划词翻译。** | `立即关闭思考模式` |
| ②首字超时**且**响应头已快速返回（< 2 秒） | **已经连上服务商了（响应只用了 {t} 毫秒），但它迟迟不返回内容。这基本是服务商自己出了状况，不是你的配置问题。可以去服务商的状态页看看，或者过一会儿再试。** | `重试` |
| ③首字超时（以上都不满足） | 等了 {n} 秒还没有任何回应。可能网络很慢，也可能你填的模型不适合划词翻译。 | `一键诊断` |
| 整体超时 | 翻译超时（{n} 秒）。文本可能太长，或者服务商这会儿很慢。 | `重试` |

> **三条首字超时规则必须严格按 ①②③ 顺序判断**，命中即停。
>
> ⚠️ **顺序不能颠倒（已踩坑）**：思考模式开着时，响应头**同样**回得很快、
> 内容**同样**迟迟不来，因此第②条会误命中，把本地原因甩锅给服务商。
> 原则是：**本地能确定的原因，优先于对远端的猜测。**
>
> 相关事实：实测思考模式下首字延迟为 3.2 / 7.1 / 12.6 秒，而首字超时上限是 10 秒。
> 也就是说在当前的 15 秒硬上限下，**思考模式实质上不可用**，
> 提示文案必须把这一点直说，不要让用户反复重试。
> 依据（真实事故复盘）：2026-08-07 DeepSeek 官方状态页出现
> 「Web/API Degraded Performance」期间，本机实测响应头 **369ms** 就返回 200，
> 但 2 分钟内一个内容块都没有。软件当时却提示「可能你填的是推理模型」，
> 把用户引向排查配置，白白折腾。**响应头快 + 内容不来 = 服务端故障**，
> 这个组合软件自己就能判断，不该让用户去猜。
| JSON 解析失败 | 服务器返回了看不懂的内容，这个地址可能不是 OpenAI 兼容接口。 | `一键诊断` |
| 剪贴板打开失败（重试后仍失败） | 剪贴板正被其他程序占用，稍等一下再试。 | — |
| 取词超时（未选中文字） | 静默，不打扰用户 | — |
| 数据库读写失败 | 历史记录保存失败，但翻译结果不受影响。详情见日志。 | `打开日志` |

> **报错里的模型名和"思考模式关没关"，以实际失败的那个档案为准**（2026-10 补充）：
> 自动降级之后最后报错的未必是当前档案，失败档案的 Id、模型名、思考开关挂在异常上一路带到报错文案。
>
> **"详情已写入日志"必须真的写了**：HTTP 错误的日志里带状态码和服务商原话（截短、脱敏），
> 异常写日志时带上整条内层原因链（以前只写外层一句 "see inner exception"，真正的原因一个字都没留下）。

### 9.2 展示位置

> ⚠️ **重要前提：不得依赖托盘气泡送达任何必须让用户看到的信息。**
> 本机用户已在 Windows 中全局关闭通知（`HKCU\...\PushNotifications\ToastEnabled = 0`），
> `NotifyIcon.ShowBalloonTip` 在这种情况下**静默失败、不报错、什么都不显示**。
> 气泡只作为"有则更好"的补充，所有关键信息必须另有可靠通道。

- 翻译相关的错误：显示在**浮窗内容区**，红色图标 + 文字 + 操作按钮
- 后台错误（数据库、日志、预热）：只写日志，不打扰用户
- 严重启动错误（无法创建数据目录、配置无法读写等）：
  用 **`MessageBox`** 显示（模态、必定可见）+ 写日志。**不要用气泡。**
- 一般性成功提示（取词成功、已复制等）：可以用气泡，但**必须同时**在界面上有
  非气泡的反馈（按钮变文字、状态栏、窗口内提示），不能只靠气泡

### 9.3 全局异常兜底

`App.xaml.cs` 中挂 `DispatcherUnhandledException`、`AppDomain.CurrentDomain.UnhandledException`、
`TaskScheduler.UnobservedTaskException`。捕获后：

1. 写完整日志
2. **本次运行的第一次**未处理异常：弹 `MessageBox` 显示
   「程序遇到了意外错误，已记录到日志。如果反复出现，请把日志发给开发者。」
   并附「打开日志文件夹」按钮
3. 同时把托盘图标切换到**警告态**（带红点），悬停提示变为
   `CtrlTranslator — 出现过错误，请查看日志（单击打开）`，此时左键单击托盘图标打开日志文件夹；
   打开过一次就算看到了，警告态随之解除，左键恢复成打开主窗口。
   之后的异常**不再弹框**（避免异常风暴把屏幕刷满）。
   （2026-10 补充：以前只改一次悬停文字，下次右键打开菜单时一刷新就被冲掉，警告态只活了几秒；
   "点击打开日志文件夹"也一直没做。）
4. 尽可能不退出程序（`e.Handled = true`）

### 9.4 自动降级的判定

由 §9.1 的同一份分类决定（`Translation/FailoverPolicy.cs`）：

| 类别 | 处置 |
|---|---|
| Key 无效、余额不足、模型不存在、配置不全 | 改用备用档案，并把这个档案**标记失效**（只有一个档案时不标记） |
| 地址 404、地区限制、内容审核、限流、5xx、其余 4xx、连不上 | 改用备用档案，**不**标记 |
| 首字超时、整体超时、返回内容看不懂 | **不降级**，直接报错 —— 已经等了十秒再换一家只会更慢 |

## 10. 一键诊断

> **M5 变更**：独立的诊断窗口已删除，12 项检查逻辑原样保留。
> 入口下放为「设置 → 翻译模型」里的**「连接检测」卡片**，结果就地展开在卡片内；
> 引导向导第 4 步失败时也会就地跑同一套检查。
> 这么改是因为原来的入口有四步深（托盘 → 设置 → 翻译服务 → 一键诊断），实际没人会点；
> 而多档案上线后，"到底哪个档案挂了"必须一眼可见。
> 下表的检查项和判据完全不变，只是**针对被选中的那个档案**运行。

每项显示 ✓ / ✗ / ⚠ + 耗时 + 说明文字，逐项执行并实时刷新。

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 配置完整性 | Base URL / Model 非空；Key 非空（本机服务可不填） |
| 2 | 地址格式 | 以 http(s):// 开头；若不含版本段（如 `/v1`）给 ⚠ 提示 |
| 3 | DNS 解析 | 能解析出主机 IP；**走系统代理时**本机解析不了只给 ⚠（代理会替我们解析） |
| 4 | 网络连接 | 不走代理：能完成 TCP + TLS 握手（10 秒上限）。**走系统代理时**：代理端口连得上 → ✓；连不上但直连可以 → ⚠（翻译会自动直连，§5.2）；都不行 → ✗ 并点名代理 |
| 5 | 身份认证 | GET `/models` 返回 200；若返回 404 则跳过此项，改由第 6 项验证 |
| 6 | 模型可用性 | 发一个 `max_tokens: 16` 的最小请求，返回 200 即可（这次没吐文字也算可用） |
| 7 | 实测翻译 | 翻译固定句 `Hello, world.`，记录**首字延迟**和**总耗时** |
| 8 | 推理模型检测 | 模型名不匹配推理模型正则，且首字延迟 < 5s，且响应无 reasoning 字段 |
| 9 | 语音引擎 | 系统中至少有一个**朗读功能能用的** SAPI 语音；有英语语音则额外 ✓ |
| 10 | 数据库 | 能打开 `history.db` 并完成一次写入-读取-删除 |
| 11 | 键盘钩子 | 钩子已成功安装（`SetWindowsHookEx` 返回非零），且划词未被暂停 |
| 12 | 运行权限 | 报告当前是否管理员；非管理员时给 ⚠ 说明 UIPI 限制 |

> 2026-10 补充：第 3、4 项以前一律直连去测，而翻译请求是走系统代理的 ——
> 实际日志里出现过代理软件没开，这两项照样打勾，到第 5 项才莫名其妙失败。
> 第 6 项以前给 1 个 token，会"先想一下"的模型刚好把它用在思考上，被误判为不可用。
> 第 9 项以前把系统里 OneCore 语音也算进去，可朗读用的接口用不了它们，诊断说"有语音"、朗读按钮却是灰的。
> 失败项的说明和浮窗报错用同一套人话（§9.1）。

检测结果下方：**「复制诊断报告」**按钮，把全部结果复制为纯文本
（Key 脱敏为 `sk-****1234` 形式；Key 不足 12 位时一位都不露），方便用户粘给 AI 求助。

## 11. 首次启动引导向导

条件：`settings.json` 不存在，或 `ApiKey` 为空时，启动后自动弹出（模态窗口，居中）。

四步，每步一页，有「上一步 / 下一步 / 跳过设置」：

1. **欢迎页** —— 一句话介绍 + 一张示意图 + 提示「你需要一个大模型服务的 API Key，
   下一步会告诉你去哪申请」
2. **选服务商** —— §5.7 的预设列表，每项一行说明 + 「去申请 Key」链接按钮；
   选「自定义」则手填 Base URL
3. **填 Key 和模型** —— 粘贴 Key（密码框；本地 Ollama 这类本机服务可以不填）；
   模型名预填推荐值，可改；有「拉取可用模型」按钮（15 秒上限）
4. **测试** —— 自动翻译 `Hello, world.`，成功则显示译文和耗时，
   按钮变为「完成」；失败则显示 §9.1 的人话错误 + 「返回上一步」+「打开一键诊断」

测试成功后，**在向导第 4 页界面内直接显示**：
「✅ CtrlTranslator 已就绪。在任意程序里选中文字，快速双击 Ctrl 试试。」
用户点「完成」写入配置并关闭向导。**不要用气泡传达这句话**（见 §9.2 前提）。

## 14. 打包与发布

```powershell
dotnet publish src/CtrlTranslator/CtrlTranslator.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -o publish
```

- **`PublishTrimmed` 必须为 false**（WPF 不支持裁剪）
- SQLite 的原生库必须靠 `IncludeNativeLibrariesForSelfExtract` 打进单文件
- 中间产物：`publish\CtrlTranslator.exe`，单文件，双击即可运行，无需安装 .NET
- 在仓库根提供 `build.ps1`，内容就是上面这条命令 + 编译 Inno 安装包 + 打开产物目录
- exe 需带图标和文件版本信息（`ApplicationIcon`、`AssemblyVersion`、`FileVersion`、
  `Product = CtrlTranslator`）

> **M6 变更：对外只发安装包，且只发一个资产。**
> Release 资产就是 `CtrlTranslator-Setup-<版本>.exe` 一个文件。
>
> - 裸 exe 不作为发布产物 —— 它没有安装记录可供覆盖，自我替换的动作在杀毒软件眼里
>   几乎等同蠕虫；它仍然会被构建，因为它是安装包的输入，也用于本机验证打包产物。
> - 不发校验文件 —— GitHub Releases API 的每个资产自带 `digest`（`sha256:…`），
>   自动更新直接用它比对下载到的文件，额外发一份校验文件纯属冗余。
>
> **校验能力的边界（有意为之）**：元数据走 `api.github.com`、安装包走
> `objects.githubusercontent.com`，两条链路互相印证，能挡住下载截断、CDN 出错、
> 传输被改动；但**挡不住仓库或 GitHub 账号被攻破**（攻击者换掉资产后 GitHub 会重算
> digest）。防那种情况需要私钥离线的非对称签名。本项目定位为自用与少数同事共享，
> 明确不把"仓库被攻破"纳入威胁模型，不引入密钥管理的长期负担。
>
> 发版前必须同步修改 `csproj` 里的 `Version` / `AssemblyVersion` / `FileVersion`，
> 否则装上新版后程序仍自认旧版本，会永远提示有更新。

### README.md 必须包含

1. 一句话介绍 + 使用方法（选中文字 → 双击 Ctrl）
2. 首次使用：去哪申请 API Key、怎么填
3. **「找不到托盘图标？」一节** —— Windows 默认把新出现的托盘图标折叠进任务栏的
   `^` 箭头里（`EnableAutoTray` 默认为 1），首次运行看不到图标是正常现象。
   告诉用户：点 `^` 展开就能看到，把图标拖到任务栏上即可固定显示；
   或走「设置 → 个性化 → 任务栏 → 选择哪些图标显示在任务栏上」打开它。
   同时说明：即使图标折叠着，气泡提示仍会正常弹出。
4. **已知限制两条**（§2.3 的 UIPI 限制与杀毒软件误报），
   以及杀毒软件误报时怎么加白名单
5. 数据存在哪（`%APPDATA%\CtrlTranslator\`）、怎么彻底卸载
6. v1.0 不包含哪些功能（§13 的清单，标为「后续版本考虑」）

## 15. 深度翻译页（主窗口）

> UI 改版时加入（2026-08，负责人确认保留），取代原「输入框手动翻译」不做的约定。
> 界面细节见 `DESIGN.md` §5.3，代码在 `UI/DeepTranslationView.xaml(.cs)` 与 `Translation/DeepPromptBuilder.cs`。

用途：坐下来精读一段文字，一次拿到**译文 + 例句 + 常见搭配**。浮窗回答"这是什么意思"，要快；
这一页回答"我该怎么写"，可以慢。两条路**互不影响**：提示词、超时、取消都是分开的，
在等深度翻译结果时随手划词，不会把深度翻译掐掉。

| 项 | 规定 |
|---|---|
| 输入 | 手动粘贴 / 输入原文，`Ctrl+Enter` 开始；单次上限 **5000 字**（超出提示分段） |
| 模式 | 下拉选四个内置模式之一或自建模式；用 `DeepPromptTemplate`，自建模式没写时沿用「通用」那套（模式卡片上标「深度未配」） |
| 译成 | 「自动检测」（与 §5.4 同一套判断）或目标语言 / 反向语言二选一 |
| 输出格式 | 三节：`【译文】`、`【例句】`、`【搭配】`（标题是解析的唯一依据，改提示词必须同步改 `DeepResultParser`）。查单词时同样加 §5.3 的词典标记 |
| 例句语言 | 固定用「反向语言」（默认英语）写例句和搭配、用「目标语言」写对照说明 —— 和本次翻译方向无关（查英文词要的是英文例句） |
| 超时 | 首字 30 秒、整体 120 秒；输出上限取档案设置与 4096 的较大值 |
| 降级 | 与划词共用同一套自动降级（§9.4） |
| 缓存 / 历史 | **既不读也不写**，结果只活在页面里 |
| 流式显示 | 译文一出来就切到结果视图边收边显示；例句和搭配收完再一次性渲染（边收边重建列表会闪） |
| 停止 | 「停止」后已经收到的部分留在屏幕上 |
| 结果提示 | 底部一行：模型 · 耗时；发生降级、代理没开自动直连、写到输出上限被截断时追加说明 |
| 复制 | 「复制译文」走 §3.2 的剪贴板服务，成功 / 失败都在底部那行给反馈 |
